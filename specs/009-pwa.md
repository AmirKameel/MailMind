# Spec 009 — PWA & Mobile

## 1. Goal
Make MailMind installable as a Progressive Web App on iOS, Android, and desktop, with a polished mobile UX and offline shell.

## 2. Non-goals
- Push notifications from server (v2).
- Native wrappers (Capacitor/TWA).

## 3. User stories
- As a user, my mobile browser prompts me to "Add to Home Screen" after a few visits.
- As a user, opening MailMind offline still shows the app shell and my last-seen inbox.
- As a user, the app icon and theme color reflect the brand.

## 4. Surface
- `public/manifest.webmanifest` — app metadata.
- `public/icons/icon-192.png`, `icon-512.png`, `maskable-512.png`.
- `app/manifest.ts` — Next.js manifest convention (TypeScript-defined).
- Service worker auto-generated by `@ducanh2912/next-pwa`.

## 5. Implementation
- `next.config.mjs` uses `withPWA(...)` (already configured in repo).
- `app/manifest.ts` exports a typed `MetadataRoute.Manifest`.
- Theme colors: `--background` light/dark, exposed as `theme_color`.

## 6. Caching strategy
- App shell (HTML/JS/CSS): stale-while-revalidate.
- `/api/*`: network-only.
- Static images: cache-first with revalidation.

## 7. Acceptance criteria
1. Lighthouse PWA audit: installable + valid manifest + valid service worker. (`npm run build && npx serve out` + Lighthouse CLI, or check on Vercel.)
2. Manifest validates against the W3C spec.
3. iOS Safari: "Add to Home Screen" works; the launched app uses the manifest icon.
4. Offline reload of `/inbox` shows the cached shell, not the browser error page.

## 8. Tests
- Unit: parse `app/manifest.ts` and assert required fields exist.
- E2E (Playwright): assert presence of `<link rel="manifest">` and the service worker registration in production builds.
